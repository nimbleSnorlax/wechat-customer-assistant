# 微信客服助手

安装版点击窗口右上角的关闭按钮后会留在 Windows 系统托盘。左键点击托盘图标可重新打开，右键选择「退出」会关闭窗口并停止本机服务。

在 [Releases](https://github.com/nimbleSnorlax/wechat-customer-assistant/releases/latest) 下载 Windows x64 安装包，安装后打开桌面上的「微信客服助手」。工作台在独立窗口中运行，使用 Windows 的 WebView2 运行时。登录电脑版微信，在首页识别账号，再选择回复方式和测试联系人。

点击顶部「暂停自动化」可以暂停回复、建群和微信窗口操作，工作台仍可查看。点击「恢复自动化」即可沿用保存的设置。关闭工作台窗口后，本机服务仍可在后台运行。

使用 AI 回复时，保存配置后可在首页启动微信历史整理。预计需要 10–20 分钟，实际耗时取决于聊天量和模型响应。整理期间可进入其他页面，完成后会收到通知。

- **运行记录**显示助手自动发送成功的回复和建群成功的结果。历史消息在语气分析时按需读取。
- **AI 配置**单独保存模型接口地址、模型名称和 AI Key。兼容 OpenAI 对话接口的模型通常使用以 `/v1` 结尾的地址。AI Key 按当前 Windows 用户加密保存在本机。
- **回复设置**可设置固定话术、适用联系人或标签，以及 AI 回复的上下文条数和补充要求。AI 试写会将示例消息与匹配的资料片段发给配置的模型。
- **回复语气**位于「知识库」。开启模仿时使用历史表达习惯，关闭时使用手动保存的基础语气。可展开「从指定会话分析语气」，选择会话和时间范围。使用模型分析时，每个会话最多提交 5 条本人回复的短样本。可将建议填入编辑框，检查后点「保存语气」。
- **建群设置**选择一位固定对接人，编辑 AI 触发条件、群名模板和群内欢迎语。收到符合条件的新私聊文字后，由当前微信将发消息的人和对接人拉进同一个群，验明三位成员后发送欢迎语。当前微信及对接人的消息会跳过建群判断。默认关闭。先配置模型，点「测试判断」可单独验证 AI 判断和话术。升级时可以沿用旧配置中唯一的对接人，确认条件后重新开启自动建群。
- **知识库**可以上传 TXT、Markdown、CSV、DOCX、PDF，每份最多 8 MB。上传扫描版 PDF 前，先转换成可复制的文字。
- **从微信历史整理**在「知识库」中运行。先保存并启用 AI 回复模式，再点「整理全部文字历史」。程序通过现有只读来源分批读取当前账号在本机可读的文字聊天，提交遮盖了常见号码、邮箱和链接的文本给已配置的模型。工作台把语气总结和可复用的知识卡片存入本机数据库，可分别修改。开启模拟语气时，AI 回复会参考语气总结。知识卡片可编辑或停用，启用后按触发词或相关性匹配。后续可点「一键重新整理」，成功后切换到新版语气和卡片，需要时点「恢复上一版」。整理在工作台后台运行，结束时发送本机通知，工作台也会保留结果提示。

在「回复设置」中先添加测试联系人，选择固定话术或 AI 生成并保存。首次配置时，「开启私聊自动回复」默认勾选，保存后才启动。固定话术无需配置模型。等顶部显示「运行中」，让测试联系人发一条新文字消息，成功的回复会写入「运行记录」。自动建群默认关闭。

开启自动回复或自动建群后，程序在后台读取新消息。只有消息符合回复范围或满足建群条件时，才尝试把当前登录的微信切到前台执行。若 Windows 未允许切换，工作台会保留待处理消息。微信回到前台后，程序会重新核对这条消息是否仍是该会话的最新来信。使用标签时先同步当前微信账号的标签。

AI 自动回复会参考同一私聊中最新来信之前的文字，默认最多 20 条。在「回复设置」的 AI 模式下可设置 5–50 条。程序按时间顺序区分客户和我方，再按当前话题匹配知识库。上下文在发送处理结束后释放。

「自动回复范围」可以选择「按微信标签」。点「读取微信标签」后，工作台会从当前账号已配置的本机资料读取标签和成员，自动回复及建群可以继续运行。勾选至少一个标签，选择「只回复所选标签」或「排除所选标签」，再保存。排除规则会跳过带有任意一个所选标签的人。助手每次发送前核对当前标签，无法确认的联系人会跳过。通讯录变化后可刷新微信标签。同一个联系人匹配多个标签时，每条消息只触发一次回复。

自动建群按触发客户逐个处理，同一客户预留或创建过群就不会重复建群。若微信确认不了群或成员，程序暂停该次操作，待人工查看。

## 从源码构建

在 Windows x64 上准备 Python、PowerShell 和 .NET 10 x64 SDK，将 SDK 安装到项目的 `.dotnet` 目录。运行以下命令准备依赖并构建。

```powershell
git clone https://github.com/scottfly189/WeChatAuto.SDK.git WeChatAuto.SDK
git -C WeChatAuto.SDK checkout --detach b9eaf32ea6f3ecd415d4f98c03fa2161610751e3
git -C WeChatAuto.SDK apply ../patches/WeChatAuto.SDK.patch
git clone https://github.com/maomao3334/wechat-cli-plus.git .thirdparty/wechat-cli-plus
git -C .thirdparty/wechat-cli-plus checkout --detach 75a322dd09c7c498536d10ff6935c5d52fd5fd2b
python -m pip install --target .python pypdf==6.21.4
pwsh -File Build-Setup.ps1 -Repository nimbleSnorlax/wechat-customer-assistant -ReaderSource .thirdparty/wechat-cli-plus
```

工作台代码位于 `server.py`、`index.html`、`installer` 和 `sdk-bridge`。SDK 补丁的许可见 [上游 MIT 许可](patches/WeChatAuto.SDK.LICENSE.txt)。

### Windows 微信客户端兼容性

- 工作台同时查找 `Weixin.exe` 和 `WeChat.exe`，再通过登录后的主窗口识别客户端。排查时记录微信「关于」中的版本号、界面语言和任务管理器中的实际进程名。
- 后台接收、通讯录、标签和历史整理读取当前账号的 4.x `xwechat_files\<账号>\db_storage`。读取器会查询微信的存储位置、Windows 的文档目录和用户目录。`WECHAT_CLI_PATH` 和 `WECHAT_CLI_CONFIG` 可用于指定已有查询配置。3.x 的 `WeChat Files` 是另一种格式，需要通过微信迁移后读取。
- 英文界面的 4.2.0.53 已在虚拟机用已有读取配置验证联系人、标签和本地文字记录。创建三人群后，工作台会核对成员。当前界面未提供可识别的群名编辑框时，保留微信默认群名，运行记录使用实际群名。首次读取和实际消息发送需要在目标账号上验收。

## 通过 GitHub 更新工作台

1. 完整安装包通过 `Build-Setup.ps1 -Repository 所有者/仓库名` 指定公开更新源。安装包名为 `WeChatAssistant-<版本>-Setup-x64.exe`。
2. 用 `pwsh -File Build-Update.ps1 -Version (Get-Content app_version.txt)` 生成对应版本的工作台更新包。
3. 把安装包和更新包上传到对应标签的 GitHub 正式发行版。工作台在前台每两分钟检查一次。发现新版后，当前版本号旁会闪烁黄点，打开详情可查看新版号并点击「下载并更新」。公开发行版可直接下载。

微信组件有改动的版本，先在 `release_update.py` 更新 `BRIDGE_VERSION`。编译安装包后运行 `python release_update.py --build-bridge`，将生成的组件包上传到同一个发行版。

更新包包含工作台代码。用户配置、知识库和本机运行依赖位于安装目录的独立文件夹里。若新版启动失败，启动程序会回到更新前的版本。联系人搜索、后台接收和历史语气分析使用安装电脑上对应微信账号的只读来源配置。
